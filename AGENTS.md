# Budget / Terra — repository instructions

Before working on any UI section or interaction, reread [docs/ui-design-contract.md](docs/ui-design-contract.md), particularly VA-01–VA-12, and [docs/ci-release-gates.md](docs/ci-release-gates.md). Apply the project AI DevKit / Superpowers methodology and Motion guidance when available. Start with current sources, use focused tests, preserve existing architecture, financial correctness and two-user shared family data. Review the entire user journey including all windows, menus, editor states and transitions. Use actual screenshots and measured geometry, not only source assertions. Do not merge a PR with red or unverified required checks or missing visual acceptance. Use Git for deployment and verify the production SHA/alias. Never test with production data. Calendar is for plans and events only. Report incomplete coverage and decisions explicitly.

Apply equivalence classes, boundaries, decision tables, state transitions, representative pairwise combinations, negative and exploratory testing to every reachable screen, dialog, menu, editor and state; document actual evidence and missing checks. Require independently expected financial values, measured layout/contrast and human visual review; green CI alone is not UX acceptance.
