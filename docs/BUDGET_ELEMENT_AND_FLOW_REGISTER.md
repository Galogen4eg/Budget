# Budget — реестр экранов, элементов и переходов (v1.0)

**Источник:** исходники `main` на коммите `4f294eb` (2026-11-23), базовая ревизия итерации **66**. Реестр ведётся в ветке `iteration/66-mandatory-payments`; изменения в production не публикуются до закрытия всей итерации.

## Как отмечаем прохождение

- `[ ]` — сценарий не подтверждён end-to-end, даже если интерфейс/код существует.
- `[x]` — конкретный сценарий подтверждён тестом; рядом обязателен номер PR/CI или иное проверяемое свидетельство.
- `[~]` — частичная проверка (например, форма открывается, но запись в Firestore не проверена).
- `[!]` — найден дефект; указываем итерацию/PR. Этот статус не снимается без проверки исправления.
- `[B]` — блокируется реальным двухпользовательским, банковским или внешним сервисом.

**Общее правило:** наличие компонента, тестов на строки исходного кода, успешная сборка и Vercel READY сами по себе не равны выполненной функциональной проверке. У каждого пункта есть постоянный ID. После каждого этапа изменяем статусы в этой таблице и протоколе итераций, а не объявляем раздел целиком готовым. Проверяем размеры 320, 390, 768, 1280, 1440, **1920×1080**; 2560 исключён.

## Обязательный CRUD-gate после регрессии сохранения операции (релиз #104)

Открытие и закрытие редактора, unit-тесты, тесты правил и успешная сборка — отдельные уровни, не подтверждение сохранения через UI. Проверять ошибки валидации/отказ записи, повторное нажатие, отмену, отсутствие ложного success, сохранение несвязанных полей.
