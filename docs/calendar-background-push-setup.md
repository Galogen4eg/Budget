# Фоновые push-напоминания календаря — развёртывание и проверка

Это отдельная интеграция Firebase Cloud Messaging (FCM) + Cloud Functions. Она НЕ развёрнута автоматически после merge PR: нужна ручная настройка Firebase и проверка на телефонах.

## Предпосылки

- Проект Firebase: `budg-1d5e0`; включены Cloud Messaging API и Firestore.
- Firebase Functions 2-го поколения и Cloud Scheduler требуют включённого биллинга (Firebase Blaze). Не включайте биллинг без проверки бюджета и условий.
- Узнайте существующий **публичный** VAPID-ключ: Firebase Console → Project settings → Cloud Messaging → Web configuration → Web Push certificates. Секретный ключ **не** помещать в клиент.
- На Vercel установите `VITE_FIREBASE_VAPID_KEY` (публичное значение) в Preview и Production; пересоберите фронтенд. Не используйте `FIREBASE_PRIVATE_KEY` в клиенте.

## Развёртывание

Из корня репозитория после аутентификации Firebase CLI:

```sh
npm install --prefix functions --no-audit --no-fund
npx firebase use --add
npx firebase deploy --only functions:calendar-push
```

Выберите ровно `budg-1d5e0` и убедитесь, что Cloud Functions API, Cloud Build, Artifact Registry, Eventarc и Cloud Scheduler разрешены для проекта.

Регистрация/отключение устройств выполняется через авторизованные callable-функции `registerCalendarPush` / `unregisterCalendarPush`; функция `sendCalendarReminders` запускается планировщиком раз в минуту. Секреты Firebase Admin находятся только в управляемой серверной среде. Функции проверяют Firestore membership. Клиент не может писать `calendarPushDevices` напрямую: эту коллекцию следует оставить закрытой для пользовательского доступа в Firestore Rules.

Firestore содержит `calendarPushDevices/{sha256(token)}` (uid, familyId, timezone, token). Для дедупликации применяется `families/{familyId}/pushDelivery/{sha256(...)}`. Для коллекции `pushDelivery` желательно настроить удаление старых записей через TTL/отдельное обслуживание, иначе журнал будет расти.

## Как проверить вручную

1. Запустить Budget по HTTPS, войти в первую семейную учётную запись, открыть «Планы» и включить напоминания. Проверить уведомление «Фоновые push подключены». Если оно не появилось, регистрация на сервере не подтверждена.
2. В Firestore Console проверить один документ `calendarPushDevices`, связанный с нужным uid/familyId; не публиковать FCM token.
3. Создать событие на 5–10 минут вперёд с напоминанием за 5 минут. Полностью закрыть вкладку/приложение. Проверить факт доставки и время на физическом Android.
4. Для iPhone/iPad: установить Budget на домашний экран через Safari (iOS/iPadOS 16.4+), открыть именно установленное веб-приложение и разрешить уведомления по нажатию кнопки. Проверить доставку при закрытом приложении. Обычная вкладка Safari на iPhone не эквивалентна установленному PWA.
5. Повторить в учётной записи второго участника: личное событие одного не должно приходить другому, общее должно приходить обоим. Проверить отмену отдельного повтора, выполненную задачу и оплаченный обязательный платёж.
6. Отключить напоминания и выйти из аккаунта; убедиться, что регистрация устройства удалена и новых push на нём нет.

## Область поддержки и ограничения

- Push-сообщения отправляются на зарегистрированные PWA-браузеры, не в нативные оболочки Capacitor Android/iOS. Для APK потребуется отдельная интеграция с Capacitor Push Notifications и нативной FCM/APNs настройкой.
- Дата и время интерпретируются в часовом поясе каждого зарегистрированного устройства. Если участники живут в разных часовых поясах, напоминания показывают указанное в событии локальное время каждого устройства — **это ограничение исходной модели данных**. Чтобы синхронизировать абсолютный момент, нужно добавить отдельную зону времени в семейное событие.
- Планировщик опрашивает зарегистрированные устройства, семью, события и настройки. Для личной семьи объём невелик; при масштабировании потребуется индекс/очередь предстоящих напоминаний.
- Дедупликация через Firestore create предотвращает одновременную отправку в разных запусках, но полностью гарантировать exactly-once доставку Push нельзя. На временной ошибке FCM попытка будет повторена, а при аварийном завершении после создания маркера возможен пропуск.
- Обязательные платежи отображаются без создания финансовых транзакций; отметка оплаты исключает их из будущих уведомлений.
- Настоящие проверки «два устройства + закрытое приложение + Safari» не заменяются unit-тестами и требуют отдельного запуска после развёртывания.
