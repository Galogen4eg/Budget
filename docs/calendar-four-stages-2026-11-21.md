# Budget: семейные планы и календарь — четыре этапа

Дата: 2026-11-21. Код: PR #23. Функции рассчитаны на существующую семейную коллекцию `families/{familyId}/events`; финансовые операции при создании календарных записей не создаются.

## 1. Надёжность
- Локальные даты без сдвига UTC на ПК и смартфоне; обработка событий через полночь.
- Сохранение, удаление и редактирование выполняются через `runTransaction` с чтением актуального серверного документа и проверкой, что исходное событие не менял второй пользователь. При конфликте выдаётся ошибка, запись не перезаписывает чужую правку.
- Изменение отдельного экземпляра повтора транзакционно добавляет исключение исходной серии и отдельное событие, не создавая дубликатов. Удаление одного экземпляра сохраняет остальные.

## 2. Повторы и семейные задачи
- Ежедневные, еженедельные, ежемесячные и ежегодные повторения, опциональная дата окончания. Для событий на 29–31 число последний день более короткого месяца используется как соответствующая календарная дата.
- Просмотр до 30 дней вперёд. Старые долгоживущие ежедневные и еженедельные серии корректно рассчитываются с переходом к ближайшим экземплярам.
- Семейные задачи с выбором участников и статусом «выполнено», отметка одного повторяющегося экземпляра, просроченные задачи в соответствующей вкладке.
- Редактор предлагает выбор между одним повторением и всей серией.

## 3. Напоминания
- Опциональные браузерные уведомления и fallback в виде сообщения внутри Budget **только пока приложение открыто**. Разрешение запрашивается по действию пользователя, имеется выключатель.
- Личные напоминания не показываются пользователю без совпадающей привязки семейного профиля; общие — доступны обоим.
- Настройки напоминаний сохраняются в семейном событии. Уже вручную оплаченные обязательные платежи не создают напоминания.
- Экспорт .ics включает VALARM, что позволяет использовать напоминания штатного календаря телефона **после ручного импорта**.
- **Ограничение:** автоматическая доставка push при полностью закрытом Budget НЕ реализована. Нужны Firebase Cloud Messaging/Web Push серверная отправка, сервис-воркер, ключи/разрешения и тесты на физических Android/iOS устройствах. Не считать сохранение настроек готовой доставкой.

## 4. Интерфейс и интеграция
- Общая адаптивная лента дел: «Сегодня», «7 дней», «30 дней», «Задачи»; видны просроченные задачи.
- Невыполненные обязательные платежи показаны как отдельные записи (без создания финансовых транзакций). По нажатию можно перейти в «Бюджет»; вручную отмеченные оплаченные платежи скрываются.
- Экспорт .ics событий на ближайший год с локально корректными датами, UTC timestamp и напоминаниями.
- Существующие календарные экраны ПК/смартфона и обработчики редактирования сохранены.

## Проверки
- Unit/регрессионные тесты: даты, отрицательный часовой пояс, конфликты через полночь, повторы, долгоживущие серии, одно исключение, одновременная правка, задачи, персональные напоминания, обязательные платежи, ICS + VALARM.
- GitHub Actions отдельно запускает тесты, TypeScript и production-сборку.
- **Не проверено:** настоящее двухклиентское обновление Firestore Emulator, интерфейс Safari/iOS, реальная доставка напоминаний в фоновом режиме, нативный импорт .ics на устройствах, полный UI E2E. Перед заявлением полной работоспособности эти проверки потребуются.
- Строгие черновые Firestore security rules из PR #16 не опубликованы, отдельного изменения правил ради календаря нет.
