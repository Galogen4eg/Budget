# Budget — аудит планов и календаря

Дата: 2026-11-21. Исходная ветка: `main`. Изменения в PR по календарю. Проверка исходников != сквозной тест UI двух аккаунтов.

| Подраздел | Подтверждение в коде | Исправление / предложение |
| --- | --- | --- |
| Создание и редактирование событий | `FamilyPlans.handleSaveEvent` ожидает `addItem/updateItem`, затем обновляет React, сообщает об успехе | Работает по структуре, но нет защиты от параллельной правки одного события двумя людьми; добавить условную транзакцию |
| Удаление событий | `FamilyPlans.handleDeleteEvent` ожидает Firestore; в `EventModal` ошибка сохраняет диалог | Сохранено; проверить при сбое сети с реальным Firebase |
| Дата события | `new Date('YYYY-MM-DD')` использовался в ПК, mobile и форме | Исправлен разбор даты как локальной календарной даты, включая дата-пикер и представления списка |
| Список текущего месяца | `FamilyPlans` вычислял upcoming/past через `new Date(`${date}T${time}`)` | Вынесена единая функция фильтрации и сортировки по локальной дате; события других месяцев по-прежнему скрыты по текущему дизайну |
| Конфликт времени | `eventConflicts` сравнивал только события с одинаковым днём | Исправлено обнаружение перекрытия через полночь, единое правило для модального редактора и экранов; подсказка свободного слота меняет и дату, если нужно |
| Назначение участников | `EventModal` при отсутствии UID-привязки подставлял первого участника | Убран чужой fallback; незаполненные участники трактуются как семейное событие, как и раньше |
| Напоминания | Значения `reminders` сохраняются в `FamilyEvent` и экспортируются в текст Telegram | Проверенной фоновой доставки напоминаний по таймеру нет; не утверждать, что запланированные уведомления доставляются |
| Голосовое добавление | Использует браузерный SpeechRecognition и Gemini при наличии ключа | Проверить разрешения Safari и сделать ручной ввод без обязательного AI |
| Повторы | Полей recurrence в `FamilyEvent` нет | Предложение: раз в неделю/месяц/год, редактирование одной серии или одного экземпляра |
| ПК и смартфон | `FamilyPlansDesktop` и `FamilyPlansMobile` используют общий список событий | Проверить 360/390/768/1440px, локальные даты, модальные окна, навигацию и статус сетевой записи |

## Рекомендуемый порядок дальнейших улучшений

1. P0: интеграционная проверка сохранения/редактирования/удаления событий двумя аккаунтами, защита от перезаписи.
2. P1: локальные уведомления при открытом приложении с честной маркировкой «в фоне не гарантируются», затем отдельный механизм push для Android/iOS, если понадобится.
3. P1: повторяющиеся события, простая форма «раз в неделю / месяц / год», семейный фильтр и события на ближайшие 30 дней независимо от текущего месяца.
4. P2: экспорт в календарь телефона по .ics и быстрые шаблоны «день рождения», «оплата», «встреча».

## Статус

Исправления в рабочей GitHub-ветке. Live Firebase, два устройства и браузерная визуальная проверка не выполнены. Не публиковать черновые Firebase security rules без согласования с PR #16.
