# Grok (xAI) integration

Personal account credentials are server-only under users/{uid}/privateIntegrations/grok (the client rules grant no access to this subcollection). Vercel production needs BUDGET_FIREBASE_SERVICE_ACCOUNT and a dedicated 32-byte hex BUDGET_GROK_KEY_ENCRYPTION_KEY; do not rotate the latter without re-encrypting existing records. No client receives plaintext keys or saves them in shared settings. The initial check uses a synthetic prompt and may incur a small API charge. Model: grok-4.3 via https://api.x.ai/v1/responses with store:false, explicit non-reasoning and bounded output. First verified key is preferred; only an explicit 401/403 revocation triggers switching to another already verified key. Quota, payment, timeouts, malformed responses and unknown outcomes never trigger hidden retries or another provider. Remove/recheck/disable in Settings → Integrations. Maximum three keys. Authentication is verified from Firebase ID tokens; the request cannot select an account. Grok receives selected confirmed budget context (up to 15 operations, category names, summary) and recent chat text; privacy mode omits the financial context, not text typed by the user. No new Grok mutation occurs without explicit confirmation; validated transaction proposals use the canonical atomic transaction save, and savings operations that need a goal must use the usual form.

Tests mock xAI; no real user key is supplied. Production smoke with a real user key remains required. Preview lacks production credentials by design. Native Android/iOS CORS and UI need separate device verification.
